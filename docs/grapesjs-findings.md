# GrapesJS 消化 AI 生成 HTML —— 实测结论

日期:2026-07-15
方法:GrapesJS 0.22.12 最小实验台(`experiment/index.html`),灌入两类典型 AI 产物:
- 样本 A:v0 风格(Tailwind 工具类、深嵌套,`samples/tailwind.html`)
- 样本 B:Bolt 风格(语义类名 + 内嵌 `<style>` + 媒体查询,`samples/plaincss.html`)

## 一、开箱即用、无需自研的部分

| 能力 | 结果 |
|---|---|
| 双击原地文本编辑(RTE) | ✅ 光标级编辑,直接可用 |
| 撤销/重做 | ✅ 结构和样式修改均可回滚 |
| 元素选中/父级导航/复制/删除 | ✅ 工具条齐全 |
| 拖拽换位(DOM 序) | ✅ 数据模型与 UI 排序器都支持 |
| 内嵌 `<style>` 解析(样本 B) | ✅ 5.3KB 全量进 CssComposer,含 `@media` 和 `:hover`,导出完整 |
| 设备切换预览(Desktop/Tablet/Mobile) | ✅ 内置 |

## 二、实测暴露的核心短板(= 自研层的需求清单)

### 1. 样式上下文丢失
`<body class="bg-slate-950 text-white">` 在导入时被丢弃,整页深色主题变白底。
→ 导入管线必须把 body/html 级样式迁移到画布 wrapper。

### 2. 样式面板对非技术用户不可用
选中 CTA 按钮,Classes 面板显示 15 个原始 Tailwind 类标签(`w-full` `bg-gradient-to-r` `from-violet-500`...),样式写入目标是整条类选择器链。
→ 需要把类翻译成人话("圆角""渐变背景"),并重新设计写入策略。

### 3. 共享类灾难(最伤的一条)
AI 生成的重复结构(三张功能卡片)类字符串完全相同。用户"改第一张卡片的背景",实际写入 `.rounded-2xl.border...` 类链规则,**三张卡片同时变色**。样本 B 一样:写入 `.card`,三张全变。
→ 必须默认元素级隔离(唯一标识),把"应用到所有同款?"做成显式询问。

### 4. 规则打架 ="越改越乱"的技术根源
同一按钮改两次背景,一次写进 `#i70s9`(ID 规则),一次写进 15 类链规则。ID 优先级压过类链,第二次修改"看起来没生效"。用户完全无法理解。
→ 自研层要保证同一元素的所有修改收敛到同一条规则。

### 5. 导出断裂(Tailwind 输入)
画布里 Tailwind 样式是 CDN 现场 JIT 生成的(12KB),`editor.getCss()` 只导出编辑器自己写的规则(423 字节)。导出 HTML 仍引用工具类 → **导出页面裸奔**。
→ 需要 Tailwind 编译管线(方向:grapesjs-tailwindcss-plugin 或导出时静态提取)。
另:仅两次改色,导出 CSS 已含 3 条互相冲突规则——"干净导出"不做规则合并就是空话。

### 6. 图层树 = 匿名 div 汤
Layer Manager 显示 Body > Div > Div > Div...,无语义名称;结构操作一步走错就出现"卡中卡"且布局崩坏。
→ 导入时做语义化聚合命名(Hero / 卡片组 / 页脚),限制非法嵌套落点。

### 7. 拖拽 ≠ 自由定位
GrapesJS 的拖拽是 DOM 树内换序,没有"像 PPT 一样拖到任意像素位置"的概念。
→ 与用户预期的差距要靠产品交互弥合(吸附提示、间距手柄),而不是改成绝对定位。

## 三、结论

**用 GrapesJS 当底座成立**:编辑器机件(选中、RTE、撤销、排序、设备预览、CSS 解析)都在,自己造这些不值。

**但直接裸用 GrapesJS 做"AI HTML 后编辑器"不成立**:上面 7 条里 5 条会直接命中目标用户(PM/运营)的第一次使用。自研层的边界已经清晰:

1. **导入管线**:body 样式迁移 + 语义化区块聚合命名 + 类去重唯一化
2. **样式写入策略**:元素级隔离为默认,同款批量修改为显式选项,规则收敛去冲突
3. **Tailwind 导出管线**:JIT 编译或静态提取,保证导出即可用
4. **交互层**:把类标签面板换成 Figma 式属性面板,把 DOM 换序包装成吸附式拖拽
